## Key Differences from Commons Lang

| Aspect | Commons Lang | PetClinic |
|--------|-------------|-----------|
| Build system | Maven | Gradle (dual-build project, Maven also available) |
| Sampling | curated_stratified (21 classes) | All classes (small project, no sampling) |
| PIT execution | Per-class (subpackage-scoped `targetTests`) | All at once (52 tests, tractable) |
| PIT output | `results/per-class/<FQN>/mutations.xml` (21 files) | `results/mutations.xml` (single file) |
| Coverage map | Generated by reproducer (too large to commit) | Included in repo (52 tests, ~80 KB) |
| PIT config | `config/pit_profile.xml` (Maven profile) | `config/pitest.gradle` (Gradle plugin block) |

### Why These Differences?

**Single mutations.xml:** PetClinic has only 52 tests. PIT continues after first kill to record additional killing tests (~2 min). Per-class scoping is unnecessary  - it's a tractability optimization for large projects like commons-lang (4692 tests).

**Coverage map included:** The coverage map is 80 KB (52 tests). Including it enables `03_evaluate.py` and `04_baselines.py` to run without Step 1 (no build required for result verification). For commons-lang, the map is too large (~15 MB) to commit.

**Gradle, not Maven:** Spring PetClinic is a dual-build project (both `pom.xml` and `build.gradle` exist). We use Gradle because the Smart Test Picker Gradle plugin was the primary development target. The evaluation protocol is identical regardless of build system.
